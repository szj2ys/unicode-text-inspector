Use the result for a human review

  1. Locate the difference. Use the UTF-16 range or Select button to return to the corresponding editor. Selection does not change text.
  2. Check the intended behavior. A joiner, directional mark, combining accent or no-break space may be necessary. Consult the author or a language reviewer before changing it.
  3. Keep an exact handoff. Export the rows and preserve their escaped and numeric representations. Similar glyphs do not guarantee identical text.

PewTranslate's guide to reviewing transcript and translation errors explains how to record uncertain wording and involve a competent reviewer. A code-unit difference does not settle meaning or translation accuracy.

How counts, names and limits work

UTF-16 code units are JavaScript string positions. A Unicode scalar value is a code point outside the surrogate range. A paired supplementary character is one scalar and two units. An unpaired surrogate is reported as an invalid UTF-16 unit, with no invented scalar or character name. Item indexes count scan items; they are not grapheme indexes.

Grapheme counts use this browser's Intl.Segmenter with granularity: "grapheme", when available. The resolved locale is shown. They are segmentation results, not a measurement of letters, glyph widths or reading comprehension. No grapheme result is claimed for text with lone surrogates. Browser Unicode data may differ.

Names come from a small built-in list, not a complete Unicode database. “Name not supplied” says nothing about assignment, validity or language. Categories use selected explicit control ranges and browser Unicode properties for marks and other format characters; they are not an exhaustive security audit.

Inspection rejects over-limit input instead of truncating it. At most 100 rows are added per display step; CSV contains all accepted rows. Each normalized preview is bounded at 16,384 units, and an excess or API failure is reported separately. Lone-surrogate inputs do not receive normalization comparisons. Editing either input clears stale results.

CSV uses quoted fields, doubled quotes and CRLF rows. Formula-like cells receive a leading apostrophe. All input-derived text is escaped ASCII; original UTF-16 hex units remain reconstructible, including unpaired surrogates. No raw-text export or automatic repair is provided.
